# SGVue Desktop — commands

Every command this project has, moved out of `CLAUDE.md` unchanged. `CLAUDE.md` keeps the ones
ordinary work needs; the dev utilities — the profilers, the parity harnesses, the fixture and
icon generators — are only here.

## The guards on Windows

The three wrappers run on Windows since 2026-09-21. The **rules** are the same — one dev
Electron at a time, only ever kill what this run started, prove nothing survived — and the
**instruments** are not, because Windows has neither `phys_footprint` nor a memory-pressure
level. `scripts/lib/win-procs.cjs` is the whole difference; `scripts/lib/electron-guard.cjs`,
the in-process guard, already worked here and is untouched.

| On macOS | On Windows |
|---|---|
| `/bin/ps -Ao pid=,comm=`, bounded at 5 s (`scripts/lib/mac-procs.cjs`) | one `powershell -NoProfile -Command` call: `Get-Process -Name SGVue,electron` with `Id,Path,WorkingSet64,PrivateMemorySize64` |
| a process is ours by the substring `/SGVue.app/Contents/` or `node_modules/electron/dist/` in its executable path; its **bundle** is everything up to `.app/` | a process is ours when its executable lies under `<ROOT>\dist\win-unpacked\`, `<ROOT>\node_modules\electron\dist\`, or the directory of a `safe-app.cjs -- <executable>.exe`; the **directory** is what a bundle means here. Compared as `realpathSync.native` + lower case + trailing separator, so `C:\Users\JANEDO~1\…` matches `C:\Users\Jane Doe\…` and `C:\dir` never claims `C:\dir2`. A null `Path` is never ours |
| `/usr/bin/footprint -p <pid>` → `phys_footprint`, bounded at 4 s, read by the one parser the in-process guard and the app use | `WorkingSet64` per process and summed, **plus** `\GPU Process Memory(pid_<pid>_*)\Dedicated Usage` from `Get-Counter` — best effort, every third poll, because one sample costs ~1.2 s. Unavailable → `gpu=n/a` once, then working set and the clock alone |
| `sysctl kern.memorystatus_vm_pressure_level`, bounded at 2 s | **nothing — there is no pressure term on Windows**, and the arming line says so |
| every 500 ms | every 1 500 ms, since each PowerShell call costs ~0.4 s |
| `kill -9` | `taskkill /PID <pid> /T /F`, so a helper tree goes with its parent |
| `node_modules/.bin/playwright` | `node node_modules/@playwright/test/cli.js` — the `.bin` shim is an extension-less POSIX script Windows cannot execute |

Limits, environment-variable names and exit codes are unchanged on both: `SGVUE_MAX_GPU_MB`
(2 500, and on Windows it bounds the GPU counter as well as one process's working set),
`SGVUE_MAX_TOTAL_MB` (9 000), `SGVUE_MAX_SECONDS`; 2 = tripped, 69 = refused, 70 = failed to
start — and **69 covers one more case, on both platforms** (macOS since 2026-09-24): a *startup*
listing that could not be made even on a retry refuses the run before anything is spawned (`REFUSED: could not list running
processes …  Nothing was started.`), because a guard that cannot see what was already running
cannot promise to kill only what it started. Every PowerShell call is bounded at 8 s and every
`taskkill` at 5 s, because `spawnSync` blocks the guard and an unbounded one would freeze the
wall-clock check; a poll whose listing failed measures nothing that tick and the clock still
runs, and a **finish** whose listing failed prints `COULD NOT LIST processes … — check by hand:
…` instead of `clean:`, the exit code unchanged. Confirm nothing survived with
`powershell -NoProfile -Command "Get-Process -Name SGVue,electron -ErrorAction SilentlyContinue | Select Id,Path"`.

`tests/unit/win-procs.test.ts` covers the pure half — the three shapes `ConvertTo-Json`
produces, and the path rule — and runs on every platform; `tests/unit/mac-procs.test.ts` does the
same for macOS — the `footprint(1)` parser on its real multi-line output, and a `/bin/ps` that
failed, timed out or printed nothing read as *could not list*, never as an empty machine.
