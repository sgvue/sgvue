## What's new in SGVue 1.6.0

**See a model arrive** — when you add a model to a view that is already open, the 3D view now shows it coming in. A thin line along the top edge of the view fills in five steps as the file is read, parsed, built, indexed and joined, and a small caption at the bottom names the file and the step (`Tower B.ifc · building geometry · 3/5`). When the model has joined, the caption says how many elements it added, or that the file could not be opened; then both fade away. Nothing is drawn over your model and nothing blocks the mouse. The first model you open from the home page loads as before.

**Projects reopen where you left them** — the main reason for this version. A saved `.sgvue` project with two or more models could reopen with its models metres apart, because each model took its own origin while they loaded side by side. Every model now shares the one origin, on every route in: opening a project, bringing a missing model back with **Locate…**, and a model still loading while another fails. Nothing is aligned automatically: a model whose file puts it in the wrong place is still shown there, so a wrong position is still visible as wrong.

**ObjectType is the element's own** — the ObjectType tile now shows the element's own ObjectType attribute, as other BIM viewers and IfcOpenShell do. It used to show the name of the element's type (a Revit "Family:Type") whenever the element had one. The type's name is still in the Schedules window's Family and Type columns, and right-click **similar** still goes by the type.

**The selection dimension fits a turned building** — on a building that is turned in its file's coordinates, the box round a selected element and its three dimensions are square with the grids again and read the element's own length, width and height. The property card's Bounding box, Footprint, Box volume and Centroid agree with it.

**Ask Vee measures a turned building the same way** — clash candidates, nearby elements, the distance between two elements and an element's size are taken along the building's own axes, the size the property card shows. A wall on a turned building used to read as a box several metres wide, and walls a metre apart "overlapped". Nothing changes for a building that is not turned.

**Fixes — projects**
- A project whose own models fail to open no longer stays stuck loading: models brought in with **Locate…** get what the project saved for them, and **Save Project** works.
- A project opened while another is still loading waits for its own models, where it used to read as loaded, and changed, before any of them were in.
- **Locate…** can be tried again with the same file after a first try that failed; it used to answer "already open in this project" until the project was reopened.
- Saving a project no longer swaps a missing model for another file of the same name. With one of the project's models missing, opening a different file of that name and saving wrote the other file in the missing model's place; the missing model is now saved as the project had it, and the other file as a model of its own.

**Fixes — Ask Vee**
- "Show only Level 5" follows the rule every other way of hiding follows: when it would leave less than 5 % of the model in view it waits for your **Apply**, and it is refused when it would leave nothing.
- A clash list that had to be cut short is in order, largest first, as the reply says.
- A spot Vee places is quoted in the unit on screen; with the unit set to ft the reply used to give metres.
- **copy csv** writes the volumes of a table that totals volumes.
- When two recent files share a name, Vee points to the sidebar's upload button, not the removed library; and a tabulated answer is no longer squeezed into one sentence.

**Fixes — main window**
- An identity tile with no value shows a dash (—) instead of an empty tile.
- The Spatial-structure card names the file's own coordinate system. Its site line always read "(SVY21)", whatever the file said.
- The Model box in **Preferences…** saves when you press Enter or leave the field, not on every keystroke.

**Fixes — Schedules**
- A filter number typed as `.5` or `1e3` is read as 0.5 and 1000 (it was read as 5 and 1), and a yes/no filter set to `✓` matches the Yes rows (it matched the No rows).
- A schedule file that names a class twice lists its rows once.
- Picking a ninth filter or a fifth sort level says the limit is reached; deleting a saved template that could not be deleted says so instead of "Deleted"; the formula guide points to the column's menu.
- The window redraws the table less: opening or closing the left panel, the calculated-value editor, the formula guide or the Templates library no longer redraws it.

**Security**
- The model database Ask Vee reads stays read-only after it is built. One of its three read-only safeguards was switched off by the step that copies the database; the other two held, and nothing wrote to it.
- A schedule file, saved template or project can no longer name a built-in word such as `constructor` as a column; such a column is dropped when it is opened.
- A schedule's formula or number format can no longer borrow a built-in word either: a formula such as `constructor(1)` is refused with the usual message, where it showed a program error as the column's text, and a display unit named `toString` no longer blanks the column's numbers.

### What works differently after updating
- **ObjectType shows the element's own value.** An element with no ObjectType of its own shows a dash on the tile, and its row in the tree no longer carries the type's name. A saved filter, filter set or project rule on ObjectType that named a type's name now matches only elements whose own ObjectType is that text, and the tree search no longer finds an element by its type's name. On an element with no ObjectType, the property card's **Same ObjectType** row counts every element with none. Right-click **similar** goes by the element's type, by its ObjectType when it has no type, and is left out for an element with neither.
- **Adding a model shows the loading line and caption** in place of the "Rebuilding federation…" badge in the middle of the view.
- **Asking Vee to show a single storey can wait for Apply** on a tall building, as isolating a few elements already did. Bringing storeys back never waits.
- **The Spatial-structure card** shows the coordinate system the file declares, and no name when the file declares none.
- **A yes/no filter value that is neither a yes nor a no spelling** (`f`, `off`, `.T.`) matches nothing in a schedule, where it used to match the No rows; and a filter or colour rule with an operator SGVue does not know is dropped when a schedule file is opened, where it used to keep every row.
- **Ask Vee's database has a `plan_box` table** beside `bbox`, for a turned building.

### Known limits
- A project is saved with its models in the order they are open; a model that was missing when the project was saved is listed last.
- Ask Vee's IFC+SG answers name each element's IFC+SG identity, but never say whether a sub-type is valid or which parameters are required: the official IFC+SG mapping is not in SGVue.
- **New conversation** forgets the conversation, not what it did: hidden elements, colours and sections from earlier answers stay until you change them.
- A value in a derived unit is shown in SI units with no unit symbol in the Schedules window, and as written in the main window.
- SGVue is not code-signed on Windows, and on a Mac it is ad-hoc signed and not notarised by Apple yet (see below).

### System requirements
- **System** — Windows 10 or 11, 64-bit; or macOS 13 Ventura or later, on Apple silicon or an Intel processor.
- **Memory** — about 8 GB for IFC files up to about 100 MB, 16 GB for files up to about 300 MB, and 32 GB for larger files, up to the 600 MB limit. With several models open at once, add their sizes together.
- **Graphics** — any graphics card with WebGL2, which every PC of the last several years has; on a PC with an NVIDIA card, SGVue uses it automatically.
- **Files** — IFC, as `.ifc` or `.ifczip`, up to 600 MB a file. A file of up to about 300 MB opens in under half a minute; from 300 MB to 600 MB, expect 30–50 seconds. A file larger than 600 MB is not opened — split it into several models.
- **Disk** — about 119 MB to download, and about 390 MB once installed, on Windows. On a Mac with Apple silicon, about 129 MB to download and 336 MB once installed; on an Intel Mac, about 136 MB and 343 MB.
- **Internet** — not needed to view models. Two things use it: a check for a newer version when SGVue starts, which sends nothing about your files or models, and Ask Vee — only if you set it up with your own Anthropic API key.

The memory and opening times were measured with SGVue 1.3.0 on one PC — Windows 11 with 64 GB of memory and an 8 GB NVIDIA graphics card — with test models generated for the purpose. A slower PC takes longer to open a file, and a real model with less repeated geometry can need more memory.

### Install or update
On Windows, download `SGVue-1.6.0-setup.exe` below and run it. Updating keeps your settings, API key, recent files, saved views and saved templates. The app is not code-signed yet, so Windows may show "Windows protected your PC" — choose **More info → Run anyway**.

On a Mac, download `SGVue-1.6.0-arm64.dmg` (Apple silicon) or `SGVue-1.6.0-x64.dmg` (Intel) below, open it and drag SGVue onto Applications; to update, do the same and choose **Replace**. Updating keeps your settings, recent files, saved views and saved templates. SGVue is not notarised by Apple yet, so the first time you open it — and again after an update — macOS says it could not check the app: open **System Settings → Privacy & Security**, click **Open Anyway** under Security, confirm, and enter your login password if asked.
