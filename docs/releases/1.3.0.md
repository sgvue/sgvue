## What's new in SGVue 1.3.0

**Models line up on the map** — SGVue now places each model where its own file says it sits on the map, whichever way the file says it: in the site's placement (Revit's *Shared Coordinates* export), in an `IfcMapConversion` (Revit's *Survey Point* or *Project Base Point* export with an EPSG code), or in the model's world coordinate system (Revit's exports without an EPSG code). Models exported these different ways used to land kilometres apart; now they line up. A map position given in feet is read as feet; a map conversion's *Scale* is not applied, because exporters write it in contradictory ways; and true north is never applied twice. If a model still cannot be lined up — its file gives no map position while another model's does, or it lands more than 5 km from the others — the Coordinate system card says so in one line. The home page says it too, under the drop zone: georeferencing is taken from the first model you open — its base point and north are the reference, and the other models are placed relative to it. Ask Vee how each model was placed.

**Units follow your model** — SGVue now opens in the first model's own unit: millimetres for a model drawn in millimetres or centimetres, metres for one drawn in metres, and feet for one drawn in feet or inches. An **ft** button joins **mm** and **m** in the Markups card, and the lengths, levels and coordinates SGVue shows follow your choice — the laser meter, the Markups card, gridline and selection dimensions, level tags and storey heights, spot coordinates, the sizes on the property card, the Section card's offset and Vee's answers, while the Coordinate system card keeps the file's own map unit. In feet, lengths and levels read as feet and inches to the nearest 1/16" (for example `12'-6 1/2"`), and coordinates as decimal feet. Property and quantity values are always shown as the file gives them. A saved session or link remembers the unit.

**The Coordinate system card is read-only** — it shows the base point the first model's file gives, in that file's own map unit (metres, feet or US survey feet), and nothing in the app changes it. You can still select a value and copy it.

**The laser meter reads both sides** — along each direction it now shows the distance from the point you clicked to the surface on each side, for example `X 1 200 + 2 300`, and the two always add up to the whole.

**Vee's answers are easier to read** — an answer starts with one sentence, its key number in bold, followed where it helps by a short list, a small table (for example counts by level or by type) or a few short paragraphs, instead of one long line.

**Canvas grid off shows what is below ground** — with the canvas grid switched off, parts below ground level are no longer dimmed; the ground and the building's shadow on it stay.

**Open source** — SGVue's source code is public at https://github.com/sgvue/sgvue, under the Apache License 2.0. The licence and the list of third-party software SGVue includes are installed with the app.

**Fixes**
- Several large models open together no longer mix up their elements. With files over about 60–70 MB each, some elements could not be selected, hidden or read on their own, and Vee's database could not be built, so questions that search the whole model failed. Sessions, links and saved views of large files now hide exactly what was hidden when they were saved, including those saved with 1.2.0.
- A file that cannot be opened now says why, wherever you pick it — the Open dialog, the Recent list or a link — as dropping it always did; before, a file over 600 MB picked in the Open dialog simply did nothing. A file over 600 MB now reads "larger than 600 MB — consider splitting it into several models".
- A zipped IFC (`.ifczip`) now opens from the Open dialog, the Recent list and a link; before, only dropping it on the window worked.
- Area and volume totals in Vee's answers carry the file's own units — square feet for a model in feet, where they always said m².

### What works differently after updating
- **The base point cannot be changed.** The Coordinate system card always shows what the first model's file gives. A base point typed into the card in 1.2.0 and saved in a session or a link is not restored, and Vee no longer offers to change the base point.
- **A model drawn in metres opens in metres**, and one drawn in feet in feet and inches, where 1.2.0 always started in millimetres. Click **mm** in the Markups card to switch back. Sessions and links saved with 1.2.0 open in the first model's own unit.
- **Some saved camera positions.** When the first model you open gives its map position in an `IfcMapConversion` or in its world coordinate system, views, sessions and links saved with 1.2.0 bring back everything but the camera position. Set the camera and save the view again.
- **Links opened in SGVue 1.2.0.** A link or session saved with 1.3.0 for two or more models, opened in SGVue 1.2.0, does not hide everything it should: elements hidden in the second and later models — and, in a large first model, some elements past its millionth line — show again, and a few elements of the second model can be hidden by mistake. Make sure the people you share links with have updated. Links and sessions saved with 1.2.0 open in 1.3.0 with the same elements hidden as in 1.2.0.

### System requirements
- **System** — Windows 10 or 11, 64-bit; or macOS 13 Ventura or later, on Apple silicon or an Intel processor.
- **Memory** — about 8 GB for IFC files up to about 100 MB, 16 GB for files up to about 300 MB, and 32 GB for larger files, up to the 600 MB limit. With several models open at once, add their sizes together.
- **Graphics** — any graphics card with WebGL2, which every PC of the last several years has; on a PC with an NVIDIA card, SGVue uses it automatically.
- **Files** — IFC, as `.ifc` or `.ifczip`, up to 600 MB a file. A file of up to about 300 MB opens in under half a minute; from 300 MB to 600 MB, expect 30–50 seconds. A file larger than 600 MB is not opened — split it into several models.
- **Disk** — about 110 MB to download, and about 390 MB once installed, on Windows. On a Mac with Apple silicon, about 128 MB to download and 328 MB once installed; on an Intel Mac, about 135 MB and 335 MB.
- **Internet** — not needed to view models. Two things use it: a check for a newer version when SGVue starts, which sends nothing about your files or models, and Ask Vee — only if you set it up with your own Anthropic API key.

The memory and opening times were measured on one PC — Windows 11 with 64 GB of memory and an 8 GB NVIDIA graphics card — with test models generated for the purpose. A slower PC takes longer to open a file, and a real model with less repeated geometry can need more memory.

### Install or update
On Windows, download `SGVue-1.3.0-setup.exe` below and run it. Updating keeps your settings, API key, recent files and saved views. The app is not code-signed yet, so Windows may show "Windows protected your PC" — choose **More info → Run anyway**.

On a Mac: the Mac disk images are added to this release after the Windows installer, once they have been tested on a Mac — until they are here, SGVue 1.2.0 for Mac is on its own release page. Download `SGVue-1.3.0-arm64.dmg` (Apple silicon) or `SGVue-1.3.0-x64.dmg` (Intel) below, open it and drag SGVue onto Applications; to update, do the same and choose **Replace**. Updating keeps your settings, recent files and saved views. SGVue is not notarised by Apple yet, so the first time you open it — and again after an update — macOS says it could not check the app: open **System Settings → Privacy & Security**, click **Open Anyway** under Security, confirm, and enter your login password if asked.
