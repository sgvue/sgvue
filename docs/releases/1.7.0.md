## What's new in SGVue 1.7.0

This version is mostly about schedules: a tidier Schedules window, Revit-style rows, formulas that build on each other, and Ask Vee setting up a whole schedule for you. The Spatial-structure card also compares your models side by side.

**A one-line view bar in the Schedules window** — what the schedule is doing now sits on one line under its name: the count of elements that pass the filters, an **All / Any** switch, short filter chips (`Width ≥ 900 mm`), sort chips with a one-click direction arrow and group button, **+ Filter** and **+ Sort / group**, and one-click switches for the grand total, grid lines and stripes. When the window is narrow, extra chips fold into a `+2` chip that lists them. Every button says what it does as soon as you point at it.

**Fewer, clearer choices in the popovers** — **Rows** is one choice of three: *Every element*, *Merge identical* or *One row per sort value*. A sort level and **Style** keep their first controls and put the rest under **More…**. The column menu's alignment and its group, filter, colour-rule, hide and remove actions are rows of icons. A table that your filters leave empty keeps its headings and names the rule that empties it.

**Revit-style rows** — with *One row per sort value*, a schedule makes one row for each value of its sort levels, as Revit does with "Itemize every instance" off. A column with a total shows that total over the row's elements, a column whose elements all read the same shows that value, and any other column reads `<varies>`.

**Formulas that use other formulas** — a calculated value can name another calculated value, such as `Waste = Volume * 1.1` after `Volume = Area * Height`, with its unit carried through. A loop is refused with the names in it. Every calculated value's name is unique, and renaming a column rewrites the formulas that use it.

**Ask Vee sets up the whole schedule** — Vee can now set everything the Schedules window can: the style (title, grid lines, stripes, text size, font, outline, bold header), each group's heading and footer, the grand-total label, colour rules on a column's cells, and a column's width, vertical heading, thousands separator, prefix and suffix, hidden zeros, unit symbol and yes/no style. A calculated column Vee made carries a small dot on its heading, and its menu shows Vee's one-line note and the formula. Vee still only changes what the Schedules window shows: never your model or your files, and every change can be undone in that window.

**IFC+SG schedules from the CoP property lists** — when you tell Vee a model is for an IFC+SG submission, it can build a schedule from the CoP 4th Edition property lists: the properties your elements carry become columns, grouped by sub-type, and the reply names the ones that are missing. Vee never says whether a model passes or fails.

**Compare your models in the Spatial-structure card** — the card now has a column for each model, with every IfcProject, IfcSite and IfcBuilding attribute and property set from each file. Rows that differ are marked, and a **differences only** switch hides the rest.

### What works differently after updating
- **A new schedule has a grand total**, and a new area, volume, mass or count column starts with Total = Sum. Schedules you saved before open exactly as they were.
- **The grand-total row says how many elements it counts** — "Grand total: 40", as Revit writes it.
- **The Rows popover's Itemise switch is gone:** its three choices replace it. The Style popover's grid lines and stripes are now on the view bar.
- **A calculated value cannot share a name with another column.** A model column that would take such a name is headed apart, for example "Volume (Qto)".

### Known limits
- A project is saved with its models in the order they are open; a model that was missing when the project was saved is listed last.
- Ask Vee's IFC+SG schedules use an independent compilation of the CoP property lists, and never say whether a model, an element or a sub-type is compliant.
- **New conversation** forgets the conversation, not what it did: hidden elements, colours and sections from earlier answers stay until you change them.
- A value in a derived unit is shown in SI units with no unit symbol in the Schedules window, and as written in the main window.
- SGVue is not code-signed on Windows, and on a Mac it is ad-hoc signed and not notarised by Apple yet (see below).

### System requirements
- **System** — Windows 10 or 11, 64-bit; or macOS 13 Ventura or later, on Apple silicon or an Intel processor.
- **Memory** — about 8 GB for IFC files up to about 100 MB, 16 GB for files up to about 300 MB, and 32 GB for larger files, up to the 600 MB limit. With several models open at once, add their sizes together.
- **Graphics** — any graphics card with WebGL2, which every PC of the last several years has; on a PC with an NVIDIA card, SGVue uses it automatically.
- **Files** — IFC, as `.ifc` or `.ifczip`, up to 600 MB a file. A file of up to about 300 MB opens in under half a minute; from 300 MB to 600 MB, expect 30–50 seconds. A file larger than 600 MB is not opened — split it into several models.
- **Disk** — about WIN_DL to download, and about WIN_INST once installed, on Windows. On a Mac with Apple silicon, about ARM_DL to download; on an Intel Mac, about X64_DL.
- **Internet** — not needed to view models. Two things use it: a check for a newer version when SGVue starts, which sends nothing about your files or models, and Ask Vee — only if you set it up with your own Anthropic API key.

The memory and opening times were measured with SGVue 1.3.0 on one PC — Windows 11 with 64 GB of memory and an 8 GB NVIDIA graphics card — with test models generated for the purpose. A slower PC takes longer to open a file, and a real model with less repeated geometry can need more memory.

### Install or update
On Windows, download `SGVue-1.7.0-setup.exe` below and run it. Updating keeps your settings, API key, recent files, saved views and saved templates. The app is not code-signed yet, so Windows may show "Windows protected your PC" — choose **More info → Run anyway**.

On a Mac, download `SGVue-1.7.0-arm64.dmg` (Apple silicon) or `SGVue-1.7.0-x64.dmg` (Intel) below, open it and drag SGVue onto Applications; to update, do the same and choose **Replace**. Updating keeps your settings, recent files, saved views and saved templates. SGVue is not notarised by Apple yet, so the first time you open it — and again after an update — macOS says it could not check the app: open **System Settings → Privacy & Security**, click **Open Anyway** under Security, confirm, and enter your login password if asked.
