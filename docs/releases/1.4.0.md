## What's new in SGVue 1.4.0

**Project files** — save a coordination review as a `.sgvue` project and open it again later, or on another computer. **File › Save Project** (⌘S on a Mac, Ctrl+S on Windows), **Save Project As…** and **Open Project…** save which IFC files are open and everything you did on top of them: model colours, hidden elements, the filter stack, sections, the camera, saved viewpoints, named filter sets, saved schedules, spot coordinates and laser measurements. The IFC files themselves are only referenced — never copied into the project and never changed — so keep them beside the project, or send them with it. While a project is open the window's title shows its name, with a `•` while there are unsaved changes, and closing the window, quitting or opening another project asks whether to save first. If a model changed since the project was saved, it opens anyway: what was saved is put back by GlobalId, and the model's row says how many saved items no longer match. If a model's file cannot be found, its row offers **Locate…** to point SGVue at it.

**Open a project with a double-click** — double-click a `.sgvue` file in Finder or Explorer, or drag it onto the SGVue window, the home page's drop zone or, on a Mac, SGVue's Dock icon. A running SGVue brings its window forward and opens it there.

**Models line up origin to origin** — every model is now drawn at its own file's coordinates, the way Navisworks places models by default, and what you see no longer depends on which model you open first. Models exported from the same coordinates — Revit's *Shared Coordinates*, for example — line up. The Coordinate system card still shows where the files say they sit on the map, and names, in one line, any model whose map position is more than 1 m or 0.1° from where its own file places it, so you know to ask for a Shared Coordinates export.

**Gridlines stay square** — when a building's grids stand at an angle on the site, Plan, the six views, the view cube, the framing of the building, the grid bubbles, the level rings, the canvas grid and the laser meter's X and Y now turn with them, so the gridlines are square on screen instead of diagonal. Only the camera turns; no model moves.

**Ask Vee in its own window** — Ask Vee now opens in a window of its own that stays above the SGVue window, so it no longer covers the model while the property card is open. Move it and resize it where you like; it comes back in the same place until you close SGVue.

**A tidier MODELS list** — click the **MODELS** header to fold the list away; open, it always shows every model. If the sidebar is too short for everything, the part under the MODELS header scrolls. Hover anywhere on a model's row to see its file's full path.

**Section cuts in model colours** — the outline of everything a section cuts is now drawn in each model's own colour, the one its MODELS row shows, so you can tell the architecture from the structure at a glance. A model with no colour of its own is still cut in the accent colour.

**Fixes**
- The property card's PredefinedType no longer shows the ObjectType text for an element whose PredefinedType is `USERDEFINED`: it shows the code as the file writes it, while the element tree's grouping and colouring by type use the effective type, as IfcOpenShell reads it.
- A model opened from a file now shows its library colour in its MODELS row and on the Spatial structure card, where it showed the colour of its place in the list.
- When two files name the same level differently, or disagree about a gridline, the gridlines, the section chips and the STOREYS list no longer depend on which file you opened first.
- Closing SGVue while another of its windows is open no longer can end in an "Object has been destroyed" error.
- Ask Vee says "Could not reach the API. Check the network." when it cannot connect.

**Security**
- A gridline's or a level's name from an IFC file is always shown as plain text; a crafted file could put markup into a grid bubble or a level tag.
- Ask Vee's database queries stop at 500 000 characters of results and say so; a crafted query could build results large enough to crash SGVue.
- **copy csv** in Ask Vee's tables makes sure a pasted value cannot become a spreadsheet formula, as the Schedules window's export already did.
- Electron 44.10.0 and other updated components, with their security fixes.

### What works differently after updating
- **Models are placed by their own coordinates, not by their georeferencing.** Models that 1.3.0 lined up through their map positions — exported with different coordinate settings — may now stand apart. The Coordinate system card names each one that does; export them from the same coordinates (for example Revit's *Shared Coordinates*) to line them up.
- **Coordinates read the files' own coordinates.** Spot coordinates and the other coordinate readouts show the coordinates in the files, where 1.3.0 showed map coordinates. The Coordinate system card still shows the base point the file gives.
- **The Coordinate system card describes the largest model**, the loaded model with the most elements that gives any georeferencing, not the first one opened. The home page's line about the first model is gone. The unit SGVue starts in is still the first model's.
- **Gridlines and the canvas grid are off when SGVue starts.** Turn them on with the **Gridlines** and **canvas grid** buttons in the toolbar. A saved session, link or view that had the gridlines on still turns them on.
- **Ask Vee is a separate window.** It opens from the same **Ask Vee** pill and closes with its × or Esc; closing it does not stop an answer that is being written.
- **The sidebar's library button is gone.** Open another file with **upload**.
- **⌘S / Ctrl+S saves the project.** The `S` key still turns snapping on and off when pressed on its own.
- **Some saved camera positions.** Views, sessions and links saved with 1.3.0 when the first model was placed by an `IfcMapConversion` or its world coordinate system bring back everything but the camera position. Set the camera and save the view again.
- **Project files need SGVue 1.4.0 or later.**

### Known limits
- A project names its IFC files and never contains them: whoever opens it needs the same files, beside the project or found with **Locate…**.
- A project does not save your Preferences, the theme, panel sizes, the selection or the Ask Vee conversation.
- A model row whose **Locate…** you dismiss with × does not offer it again until the project is reopened.
- A project on a network share opens by double-click or **File › Open Project…**, not by dragging it onto the window.
- On Windows the installer registers `.sgvue` for your user only. If Windows asks which app should open a `.sgvue`, pick SGVue; the file icon may appear only after Explorer refreshes. On a Mac, Finder learns the file type once SGVue has been opened.
- SGVue is not code-signed on Windows, and on a Mac it is ad-hoc signed and not notarised by Apple yet (see below).

### System requirements
- **System** — Windows 10 or 11, 64-bit; or macOS 13 Ventura or later, on Apple silicon or an Intel processor.
- **Memory** — about 8 GB for IFC files up to about 100 MB, 16 GB for files up to about 300 MB, and 32 GB for larger files, up to the 600 MB limit. With several models open at once, add their sizes together.
- **Graphics** — any graphics card with WebGL2, which every PC of the last several years has; on a PC with an NVIDIA card, SGVue uses it automatically.
- **Files** — IFC, as `.ifc` or `.ifczip`, up to 600 MB a file. A file of up to about 300 MB opens in under half a minute; from 300 MB to 600 MB, expect 30–50 seconds. A file larger than 600 MB is not opened — split it into several models.
- **Disk** — about 110 MB to download, and about 390 MB once installed, on Windows. On a Mac with Apple silicon, about 128 MB to download and 328 MB once installed; on an Intel Mac, about 135 MB and 335 MB.
- **Internet** — not needed to view models. Two things use it: a check for a newer version when SGVue starts, which sends nothing about your files or models, and Ask Vee — only if you set it up with your own Anthropic API key.

The memory and opening times were measured with SGVue 1.3.0 on one PC — Windows 11 with 64 GB of memory and an 8 GB NVIDIA graphics card — with test models generated for the purpose. A slower PC takes longer to open a file, and a real model with less repeated geometry can need more memory.

### Install or update
On Windows, download `SGVue-1.4.0-setup.exe` below and run it. Updating keeps your settings, API key, recent files and saved views, and registers `.sgvue` project files for your user. The app is not code-signed yet, so Windows may show "Windows protected your PC" — choose **More info → Run anyway**.

On a Mac: the Mac disk images are added to this release after the Windows installer, once they have been tested on a Mac — until they are here, SGVue 1.3.0 for Mac is on its own release page. Download `SGVue-1.4.0-arm64.dmg` (Apple silicon) or `SGVue-1.4.0-x64.dmg` (Intel) below, open it and drag SGVue onto Applications; to update, do the same and choose **Replace**. Updating keeps your settings, recent files and saved views. SGVue is not notarised by Apple yet, so the first time you open it — and again after an update — macOS says it could not check the app: open **System Settings → Privacy & Security**, click **Open Anyway** under Security, confirm, and enter your login password if asked.
